# Why plot data?

Data visualization is an important part of scientific data analysis. A well-designed plot can help you quickly identify patterns, differences, relationships, and unusual observations that may be difficult to see in a table of numbers.

In this lesson, we will learn how to use **`ggplot2`** to turn data into informative visualizations.

Plots are used to convey research findings in many different venues including posters presentations or publications. There are different kinds of plots that are used for different purposes including:

  + **Bar Plot:**  Shows magnitude or mean/variation across categories 
  + **Histogram:** Shows occurrence along numeric intervals
  + **Density Plot:** Shows distribution along numeric intervals 
  + **Box and Whisker Plot:** Shows summary statistics 
  + **Scatter Plot:** Shows correlation 
  + **Heatmap:** Allows for visualization of correlations and clustering

# Using `ggplot2()` to Build a Plot 

**Start with a biological question**

We will learn how to build a ggplot2 visualization by starting with a biological question:

  _Do penguins with deep beaks also have long beaks?_

  ![Culmen Depth](../../img/culmen_depth.png){ width="400" }
</figure>

This might seem like a simple question, but it gives us an opportunity to explore two variables in our dataset and look for a relationship between them.

Before writing any code, let's think about what we would need to plot to answer this question.

We have two measurements:

  + **bill depth** — how deep the penguin's bill is
  + **bill length** — how long the penguin's bill is

A scatterplot is a useful starting point because it allows us to examine the relationship between two continuous variables. Each point will represent one penguin.

## Building our first plot with `ggplot()`

One of the key ideas behind `ggplot2` is that we build a plot by adding components together. These components are often called **layers**, and we add them using the `+` operator.

At its most basic level, a `ggplot2` plot needs to know:

  1. What data are we plotting?
  2. Which variables should be represented in the plot?
  3. How should those variables be represented?

As input `ggplot()` requires a data frame as its first argument.

```r
#ggplot(penguins) #what happens? 
```

At this point, we have initialized a plot, but there is nothing to see yet. We have told `ggplot2` which data to use, but we have not told it what to plot.

Next, we need to tell `ggplot2` which variables we want to visualize. Any plot created with `ggplot()` **must have at least one `geom_` or geometric object**. Functions starting with the prefix `geom_` create a visual representation of data.

* points (`geom_point`, `geom_jitter` for scatter plots, dot plots, etc)
* lines (`geom_line`, for time series, trend lines, etc)
* boxplot (`geom_boxplot`, for boxplots)

You can add a `geom_` to a plot using the `+` operator. The `+` sign goes at the end of the line, not in the beginning.

```r
#ggplot(penguins) + 
  #geom_point() # note what happens here
```

You will find that even though we have added a layer by specifying `geom_point`, we still get an error. This is because each type of `geom_` has a **required set of aesthetics elements** to be set. Aesthetic mappings are set with the `aes()` function and can be set inside `geom_point()`. Examples of aesthetics include:

* position (i.e., on the x and y axis)
* color ("outside" color)
* fill ("inside" color) 
* shape (of points)
* line type
* size

We will begin by specifying which variables we want to display on the x- and y-axes. Because we are creating a scatter plot with geom_point(), each penguin will be represented by a point, with its position determined by these two variables.

Let's put `bill_depth_mm` on the x-axis and `bill_length_mm` on the y-axis:

```r
ggplot(data = penguins) +
  geom_point(mapping = aes(x = bill_depth_mm,
                           y = bill_length_mm))
```

This plot allows us to explore our original question: Do penguins with deeper bills also have longer bills?

But our dataset contains much more information about each penguin. We might be wondering about the seemingly three distinct clusters and what this could be possibly be. We can begin by adding information such as where the penguins live.

## Mapping additional variables

So far, each point represents a penguin based on two variables: bill depth and bill length. But what if we want to include information about a third variable in the same plot?

One way to do this is by using color. We can map island to the **color aesthetic**:

```r
ggplot(data = penguins) + 
  geom_point(mapping = aes(x = bill_depth_mm, 
                            y = bill_length_mm, 
                            color = island))
```

Now the position of each point tells us about bill depth and bill length, while its color tells us which island that penguin came from. Notice that `island` is categorical variable with a discrete range of possible values: Biscoe, Dream, and Torgersen. `ggplot2` automatically assigns a different color to each category. This is an example of an aesthetic mapping: we are telling `ggplot2` to use the value of a variable to determine a visual property of the plot.

We can use *other* aesthetics in the same way. For example, we can use **shape** to distinguish among penguin species.

This allows us to ask a more specific biological question:

  _Which species of penguin is found on all three islands?_

```r
ggplot(data = penguins) + 
  geom_jitter(mapping = aes(x = bill_depth_mm, 
                            y = bill_length_mm, 
                            color = island,
                            shape = species))
```

To review, we are displaying information about **four variables** in a single visualization:

  + bill_depth_mm → x-position
  + bill_length_mm → y-position
  + island → color
  + species → shape

This is one of the most powerful features of `ggplot2`: we can communicate information about **multiple variables** by mapping them to different visual properties.

## Mapping versus setting an aesthetic

There is an important distinction between mapping an aesthetic to a variable and setting an aesthetic to a specific value.

!!! example "Class Exercise" 

      Compare the plots generated by the two codes below: 

      ```r
      ggplot(data = penguins) + 
        geom_point(mapping = aes(x = bill_depth_mm, 
                                y = bill_length_mm),
                  color = "blue")
      ```
      
      ```r
      ggplot(data = penguins) + 
        geom_point(mapping = aes(x = bill_depth_mm, y = bill_length_mm), 
        color = "blue")
      ```

In the first plot, color is inside `aes()`, so color is mapped to a variable. Each island receives a different color. In the second plot, color is outside `aes()`. Color is not being mapped to a variable. Instead, we are telling `ggplot2` to make every point blue.


## Switching Geometrical objects

So far, we have used `geom_point()` to create scatterplots. A scatterplot is useful when we want to examine the relationship between two continuous variables. But what if our question changes?

  **How does bill length vary among penguin species?**

This is a different type of question. Rather than focusing on the relationship between two measurements, we want to compare the distribution of a measurement across groups. This is where choosing a different `geom_` becomes useful.

### Using `geom_boxplot()`

A boxplot provides a compact way to summarize the distribution of a continuous variable within different categories. Let's use `geom_boxplot()` to compare bill length among the three penguin species:

```r
ggplot(data = penguins) + 
  geom_boxplot(mapping = aes(x = species, 
                             y = bill_length_mm))
```

Take a moment to look at what this plot is showing us.

Each box represents the distribution of bill lengths for one species. The:

  + middle line represents the median
  + bottom and top of the box represent the first and third quartiles (25th and 75th percentiles)
  + whiskers extend to observations within 1.5 × the interquartile range (IQR)
  + individual points beyond the whiskers represent potential outliers

So, unlike our scatterplot, we are no longer looking at one point per penguin to examine a relationship between two measurements. Instead, the boxplot gives us a summary of the distribution of bill length within each species.

### Adding layers

Boxplots are useful summaries, but they hide some information about the individual observations.

For example, we might want to see both:

  + the overall distribution of bill lengths for each species, and
  + the individual penguins that make up those distributions.

We can do this by adding another **geometric layer** to our plot. In the following plot we will place the boxplots **over** jittered points to see the distribution of outliers more clearly. `geom_jitter()` is similar to `geom_point()`, but it adds a small amount of random variation to the position of the points. This helps separate observations that would otherwise overlap.

```r
ggplot(data = penguins) + 
  geom_jitter(mapping = aes(x = species, 
                            y = bill_length_mm, 
                            color = species)) +
  geom_boxplot(mapping = aes(x = species,
                             y = bill_length_mm))

```

We have now layered two geometries:

  + `geom_jitter()` shows the individual observations.
  + `geom_boxplot()` summarizes the distribution of those observations.


Because both layers use the same x- and y-axis mappings, we can move those mappings into the main `ggplot()` function and rewrite the code as:

```r
ggplot(data = penguins, mapping = aes(x = species, y = bill_length_mm)) + 
  geom_jitter(aes(color = species)) + 
  geom_boxplot()
```

Here, we've set the transparency of the boxplot to .6, so we can see the points behind it, and also mapped color to island in the points. It is recommended to build each layer separately and then moving common arguments up to the "parent" function.

We can use linear models to highlight differences in dependency between bill length and body mass by island. Notice that we added a separate argument to the `geom_smooth()` function to specify the type of model we want `ggplot2` to built using the data (linear model). The `geom_smooth()` function has also helpfully provided confidence intervals, indicating "goodness of fit" for each model (shaded gray area). For more information on statistical models, please refer to help (by typing `?geom_smooth`)

```r
ggplot(data = penguins, 
       mapping = aes(x = bill_depth_mm, 
                     y = bill_length_mm)) +
  geom_point(alpha = 0.5) +
  geom_smooth(method = "lm")
```

In the graph above, each geom inherited all three mappings: x, y and color. If we want only single linear model to be built, we would need to limit the effect of color aesthetic to only `geom_point()` function, by moving it from the “parent” function to the layer where we want it to apply. Note, though, that because we want the color to be still mapped to the species variable, it needs to be wrapped into `aes()` function and supplied to mapping argument.


```r
ggplot(data = penguins, 
       mapping = aes(x = bill_depth_mm, 
                     y = bill_length_mm,
                     color = species)) +
  geom_point(alpha = 0.5) +
  geom_smooth(method = "lm")
```

The data actually reveals something called the “simpsons paradox”. It’s when a relationship looks to go in a specific direction, but when looking into groups within the data the relationship is the opposite. Here, the overall relationship between bill length and depths looks negative, but when we take into account that there are different species, the relationship is actually positive.

## Sub-plots (plot panels)

Often, we'd like to create the same set of plots, but as distinctly different subplots.
This way, we don't need to map so many aesthetics (it can end up being really messy).

Lets say, the last plot we made, we want to understand if there are also differences between male and female penguins.

In ggplot2, this is called a "facet", and the function we use is called either `facet_wrap` or `facet_grid`. 

```r
ggplot(penguins, 
      aes(x = bill_depth_mm, 
          y = bill_length_mm,
          color = species)) +
  geom_point(alpha = 0.5) +
  geom_smooth(method = "lm") +
  facet_wrap(~ sex)
```

The facet’s take formula arguments, meaning they contain the tilde (~). 

This plot looks a little crazy though, as we have penguins with missing sex information getting their own panel, and really, it makes more sense to compare the sexes within each species rather than the other way around.

## Selecting columns

Let us first talk about selecting columns. In {dplyr}, the function name for selecting columns is `select()`! Most {tidyverse} function names for functions are inspired by English grammar, which will help us when we are writing our code.

```r
knitr::include_graphics("fig/03-selecting.gif")
```

To select data, we must first tell select which data set we are selecting from, and then give it our selection. Here, we are asking R to `select()` from the `penguins` data set the `island`, `species` and `sex` columns

```r
select(penguins, island, species, sex)
```

When we use `select()` we don't need to use quotations, we write in the names directly. 


We can also use the numeric indexes for the column, if we are 100% certain of the order of the columns:

```r
select(penguins, 1:3, 6)
```

In some cases, we want to remove columns, and not necessarily state all columns we want to keep. 
Select also allows for this by adding a minus (`-`)  sign in front of the column name you don't want.

```r
select(penguins, -bill_length_mm, -bill_depth_mm)
```

### Tidy selections

These selections are quite convenient and fast! But they can be even better. 

For instance, what if we want to choose all the columns with millimeter measurements? That could be quite convenient, making sure the variables we are working with have the same measurement scale.

We could of course type them all out, but the penguins data set has names that make it even easier for us, using something called `tidy-selectors`.

Here, we use a tidy-selector `ends_with()`, can you guess what it does? yes, it looks for columns that end with the string you provide it, here `"mm"`.

```r
select(penguins, ends_with("mm"))
```

So convenient! There are several other tidy-selectors you can choose, [which you can find here](https://dplyr.tidyverse.org/reference/select.html), but often people resort to three specific ones:

- `ends_with()` - column names ending with a character string  
- `starts_with()` - column names starting with a character string  
- `contains()` - column names containing a character string
