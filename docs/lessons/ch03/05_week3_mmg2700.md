+ Let's take a moment to really dig into this.
+ The first column contains HGNC gene symbols. These are the gene names you are probably most familiar with. However, there are several other gene identifier systems that are commonly used in bioinformatics pipelines.
+ The third column contains the GEO sample-specific accession number. This is a unique identifier assigned to each sample in the Gene Expression Omnibus (GEO). When we deposit NGS data into GEO, each sample is assigned its own accession number.
+ The other columns I want to point out are the Ensembl ID and Entrez ID columns. These are two commonly used systems for identifying genes. Entrez Gene IDs are maintained by NCBI, while Ensembl IDs are provided by the Ensembl project at EMBL-EBI.
+ You might think that we could easily convert one gene ID system to another, but it isn't always that simple. Different databases use different annotation methods, algorithms, and criteria. As a result, one Entrez ID does not always map perfectly to a single Ensembl ID, and some identifiers may have multiple mappings or no current mapping at all.

## Why is this important? 

Gene names are for humans; gene IDs are for databases and computational pipelines—and moving between those systems is not always straightforward.

## Subsetting rows using values in a column 

What happens if we want a specific gene of interest? 

First, we can access a single column: 

```r
rna$gene # this allows us to select a column 
```

Now we ask a question about that column: 

```r
rna$gene == "Asl" # this does not return data, it returns TRUE/FALSE
```

We can use this logical vector to keep the rows we want:

```r
rna[rna$gene == "Asl", ] # keep only the rows which are TRUE
```

+ rows where the condition are TRUE are kept
+ the blank after the comma means *keep all columns*

## Adding multiple conditions with `&`

Sometimes we want rows that meet more than one condition. To combine row conditions we use: `&` 

```r
rna$gene == "Asl" & rna$tissue == "Cerebellum"
```
